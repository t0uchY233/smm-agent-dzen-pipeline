# Выпуск через Codex без n8n

Статус: реализован локальный CLI; внешняя приёмка требует авторизации и согласованного тестового выпуска. Наличие кода и unit-тестов не подтверждает публикации на реальных площадках.

## 1. Исходное состояние

Присланный SOP описывал сценарий → запись → монтаж → Drive → n8n → YouTube → согласование Telegram и Дзена → автоматический выпуск. В репозитории README, RECIPE и действующие навыки уже описывали прямую загрузку только YouTube. Сохранённые n8n JSON содержали YouTube uploader и Telegram/WordPress publisher; отдельного опубликованного и проверенного пути Дзена не было. Исторический `docs/user-story-status.md` не является свидетельством работоспособности облачных сервисов.

| Given | When | Then по старому SOP |
|---|---|---|
| Тема | Пользователь обращается к Codex | Уточнение даты и кейса, сводка |
| Сводка | OK | Текст суфлёра и DOCX |
| DOCX | Пользователь записывает видео | Raw MP4 |
| Raw MP4 + DOCX | Монтаж | Rendered MP4 |
| Rendered MP4 | Загрузка в Drive | n8n загружает YouTube и присылает ссылку |
| YouTube URL | `/publish-from-script` | Превью Telegram и статьи |
| Превью | OK и наступление срока | Публикации и уведомление |

Новая цепочка полностью исключает n8n, Drive, Sheets, WordPress и блог veselkov, в том числе хранение изображений и RSS. Исторические интеграции находятся в `archive/retired-2026-09-18/` и не запускаются действующими командами.

## 2. Целевой контракт

### Ответственность и SOP

1. Пользователь задаёт тему, материалы и будущее время по Москве.
2. Codex показывает сводку; после OK создаёт текст и DOCX со встроенными изображениями. Выдуманный кейс обозначается как условный.
3. Пользователь записывает видео. Codex монтирует его по DOCX и проверяет кадры, все визуалы, непрерывный PiP, звук и длительность.
4. Codex читает DOCX через `tools/read_docx.py`, создаёт описание и локальную обложку YouTube, видео с текстом Telegram и статью Дзена. Тексты проходят tone-of-voice → ru-text → slop-stop. Показывается общий комплект, каналы и дата.
5. После утверждения текущей версии Codex загружает YouTube, получает URL, подставляет его вместо `{youtube_url}`, назначает Telegram и Дзен. Подстановка этой ссылки входит в утверждение и не требует повторного OK. Иные правки материалов требуют нового утверждения.
6. Codex проверяет серверные состояния и сообщает результат по каждой площадке. Отключение компьютера после подтверждённой постановки не отменяет серверное расписание.

Команды: `/video-script`, `/render-docx-visuals "<raw_mp4>" --docx "<docx_path>"`, `/publish-from-script "<rendered_mp4>" --docx "<docx_path>"`. Последняя по умолчанию готовит три площадки; явно ограниченный запрос выполняется только для выбранных. YouTube URL означает существующий ролик: без автоматической перезагрузки или изменения опубликованного материала.

### Подключения

Установить Python-зависимости: `python -m pip install -r requirements-publishing.txt`. FFmpeg/ffprobe нужны для проверки монтажа. Настройки перечислены в `.env.example`; заполнить локальный `.env`, не выводить его в чат.

- Telegram: `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` из https://my.telegram.org, `TELEGRAM_CHANNEL_ID` (рекомендуется числовой `-100…`), `TELEGRAM_SESSION_PATH=.local/auth/telegram.session`. `python tools/publish_release.py auth-telegram` запускается пользователем в локальном терминале; телефон, код и пароль вводятся интерактивно, не через чат. Нужен пользовательский аккаунт с правом публикации в канале, не BotFather.
- YouTube: включить Data API v3, создать OAuth Web application, задать `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`, `YOUTUBE_CHANNEL_ID` в `.env`. В Authorized redirect URIs добавить в точности `http://localhost:8765/`, включая завершающий слеш; Authorized JavaScript origins не нужны. Команда `python tools/publish_release.py auth-youtube` временно запускает локальный callback-сервер и открывает OAuth-вход. Порт 8765 должен быть свободен; при конфликте он не заменяется случайным портом. Токены сохраняются автоматически в `YOUTUBE_TOKEN_PATH=.local/auth/youtube-token.json`. Пара ID/Secret имеет приоритет над JSON; неполная пара вызывает ошибку. При смене клиента повторить авторизацию. Резервный вариант: если оба поля пусты, OAuth Desktop JSON читается из `YOUTUBE_CLIENT_SECRETS_PATH=.local/auth/youtube-client.json`. Используются scopes youtube.force-ssl (в том числе videos.update для назначения времени) и youtube.readonly.
- Дзен: авторизованный профиль Chrome CDP, точный URL целевого канала в комплекте. Основной путь — `dzen-publish/ensure_cdp_chrome.ps1` и `dzen-publish/publish_dzen.py`; `--schedule YYYY-MM-DDTHH:MM` назначает отложку. Не предполагается наличие публичного publishing API. Browser Use не используется, пока CDP-скрипт не вернул фактическую ошибку.
- `PUBLISH_TIMEZONE=Europe/Moscow`. Секреты, токены и сессии хранятся вне Git. Встроенной генерации изображений ключ API не нужен.

### Комплект и состояние

DOCX и MP4: `YYYY-MM-DD-HHMM-Русский заголовок` с разными расширениями. Источник текста — DOCX; готовый MP4 — из `.tmp/rendered/`. Явное время пользователя приоритетнее имени. Если оно не задано, Codex извлекает его через `read_docx.py`; CLI получает уже разрешённое значение. Если осталось меньше минуты, согласовать новую дату; никогда не подставлять прошедшее время в API.

Каталог `.tmp/publishing/<docx-base>/` содержит `manifest.json`, `state.json`, `events.jsonl`, разрешённые тексты `telegram.txt`, `dzen.md`, браузерные доказательства. Этот каталог является рабочим журналом и не подлежит автоматической очистке. Проверить старый `.tmp/youtube/<docx-base>/upload-state.json`, `publish-log.md` и канал до новой загрузки.

Минимальный manifest (пути относительно корня проекта; разрешены абсолютные локальные пути):

```json
{
  "docx_path": ".tmp/teleprompter/2030-01-20-1400-Тема.docx",
  "video_path": ".tmp/rendered/2030-01-20-1400-Тема.mp4",
  "render_report_path": ".tmp/rendered/2030-01-20-1400-Тема.qa.json",
  "thumbnail_path": ".tmp/covers/Тема.png",
  "title": "Тема",
  "description": "Утверждённое описание из DOCX",
  "made_for_kids": false,
  "scheduled_at": "2030-01-20 14:00",
  "timezone": "Europe/Moscow",
  "platforms": ["youtube", "telegram", "dzen"],
  "youtube_channel": "UC_CHANNEL_ID",
  "telegram_channel": "-1001234567890",
  "dzen_channel": "https://dzen.ru/CHANNEL",
  "telegram_text": "Утверждённый текст\n{youtube_url}",
  "dzen_article": "Утверждённая статья\n{youtube_url}",
  "dzen_images": []
}
```

Для существующего ролика добавить `youtube_id`. Если выбраны только Telegram/Дзен, указать ID уже проверенного ролика для ссылки. `made_for_kids` определяется содержанием, пример `false` не является универсальным значением.

Отчёт QA готовит агент по результатам монтажа; он должен фиксировать присутствие всех визуалов, PiP, звук и длительность, а не содержать неподтверждённое «OK». SHA-256 утверждения охватывает manifest и содержимое всех перечисленных файлов. Новая версия не переписывает уже назначенные серверные публикации: сначала сверить их и согласовать изменение отдельно.

CLI:

```text
python tools/publish_release.py prepare --manifest <prepared-json>
python tools/publish_release.py status --release <release-dir>
python tools/publish_release.py approve --release <release-dir> --revision <hash-from-preview>
python tools/publish_release.py schedule-youtube --release <release-dir>
python tools/publish_release.py render-texts --release <release-dir>
python tools/publish_release.py schedule-telegram --release <release-dir>
python tools/publish_release.py check-youtube --release <release-dir>
python tools/publish_release.py check-telegram --release <release-dir>
```

`approve` запускается агентом только после OK соответствующего превью или уже данного явного утверждения этой версии. Само поручение реализовать инструменты не утверждает конкретный выпуск.

Статусы отдельно по площадкам: `prepared`, `uploaded`, `scheduled`, `published`, `failed`. Технические состояния `uploading`, `sending`, `unconfirmed` означают незавершённую сверку. Ошибка не стирает известные ID. Блокировка `.lock` исключает параллельную работу с одним выпуском; после аварии её удаляют только после проверки процесса.

### YouTube

Проверить OAuth-канал, загрузить приватно, сохранить ID сразу после ответа, установить thumbnail, повторно проверить время и назначить `publishAt`. Прочитать результат через API, отдельно сообщить состояние обработки. Повторный запуск проверяет известный ID; после неопределённого upload без ID новая загрузка блокируется. Искать ролик в Studio по названию и тегу `codex-release-<release_id>`, затем записать наблюдение через `record-browser`.

API-проекты могут быть ограничены приватными загрузками до аудита. Успешный HTTP-ответ сам по себе не доказывает доступность публичного выпуска: проверить расписание и ограничения в Studio при первой настройке проекта. При ограничении продолжить через Studio с существующим роликом, не загружая копию вслепую. Автоматического обхода ограничений нет.

### Telegram

Telethon использует пользовательскую MTProto-сессию. Проверить канал и право post_messages, загрузить файл, затем повторно проверить запас времени и передать серверную дату. Получить список отложенных сообщений и сверить ID, содержание, медиа и дату. Длинный текст делится по лимитам сервера: у видео короткая подпись с URL, остальные части — отдельные сообщения на то же время; атомарность и порядок отдельных сообщений не гарантируются.

После таймаута без ID не повторять отправку автоматически. Сначала осмотреть отложку. Для найденной части выполнить `reconcile-telegram --release <dir> --part-index <индекс-с-нуля> --message-id <ID-в-отложке>`: CLI сверяет канал, текст, дату и параметры медиа перед привязкой. Идентичность видео дополнительно проверить визуально; размер файла не доказывает совпадение содержимого. Если объект не найден, не сбрасывать попытку без ручной проверки канала. Исчезновение сообщения из очереди не означает публикацию: оно могло быть удалено. При поздней проверке CLI ищет уникальное совпадение текста/медиа в последних 200 сообщениях и временном окне 0–5 минут после срока; за пределами этой выборки требуется браузерная сверка. При неоднозначности сохранить `unconfirmed`. Превышение размера видео блокирует отправку и требует согласования отдельной Telegram-версии, не скрытой замены ссылкой.

### Дзен и CDP-подтверждения

Прочитать навык `dzen`, запустить `dzen-publish/ensure_cdp_chrome.ps1`, затем выполнить read-only `dzen-publish/publish_dzen.py --healthcheck` и только после успеха передать `dzen.md`, локальные изображения и `--schedule` в `dzen-publish/publish_dzen.py`. Health-check и подключение скрипта ограничены по времени и повторяют соединение; при таймауте до открытия редактора повторить helper и health-check один раз, сохраняя состояние `unconfirmed`, а не `failed`. Скрипт проверяет загрузку изображений и штатно задаёт дату. Проверить через CDP URL/ID, канал, дату и часовой пояс, затем сохранить текст наблюдения. Browser Use или Computer Use допустимы только после конкретной ошибки редактора CDP-скрипта при успешном health-check. При отсутствии функции или авторизации сохранить материалы и точный блокер.

`record-browser --release <dir> --platform dzen|youtube --evidence <json>` фиксирует наблюдение, но не выполняет браузерное действие и не подтверждает его автоматически. Поля JSON: `url`, `channel`, `status`, `observed_at` (ISO с часовым поясом), `evidence_path`, для scheduled — `scheduled_at`, для YouTube — `id`. Канал и срок должны совпадать с комплектом. Публикация Дзен не зависит от WordPress, RSS или публичного хранилища обложек.

Итог — подтверждённая отложка по каждой выбранной площадке. Если одна не завершена, остальные не откатывать и не дублировать. Фактический выход проверяется отдельным запуском; постоянный монитор и автоматическое уведомление после выхода в эту версию не входят.

## 3. Приёмка Given / When / Then

| ID | Given | When | Then |
|---|---|---|---|
| S01 | Тема, будущая дата | OK сценария | DOCX, визуалы и обозначенные условные кейсы |
| S02 | Raw и DOCX | Монтаж | Все визуалы, непрерывный PiP, проверенные звук и длительность |
| S03 | Готовый комплект | Запрос выпуска | Общее превью каналов, материалов и времени |
| S04 | Нет утверждения или файлы изменены | Попытка публикации | Сетевые изменения блокируются |
| S05 | Утверждённый комплект | Загрузка YouTube | ID, URL, thumbnail, проверенные расписание и обработка |
| S06 | Ограниченный API-проект | Планирование | Studio с проверкой существующего ролика |
| S07 | URL и Telegram-материалы | Планирование | Все сообщения в серверной отложке правильного канала |
| S08 | Длинный текст | Подготовка Telegram | Короткая подпись и дополнительные сообщения в пределах лимитов |
| S09 | Дзен авторизован | Планирование статьи | Прямая загрузка через CDP и подтверждение срока |
| S10 | До срока меньше минуты | Назначение | Запрос новой даты без немедленной отправки |
| S11 | Таймаут или повтор | Возобновление | Сверка существующих объектов без слепых дублей |
| S12 | Частичный сбой | Завершение | Сохранены успехи и явный блокер по оставшейся площадке |
| S13 | Все расписания подтверждены | Завершение | «Запланировано», а не «Опубликовано» |
| S14 | Неверный канал/нет прав/истёк вход | Проверка подключения | Публикация блокируется до исправления |
| S15 | Слишком большое видео | Отправка Telegram | Ошибка, без скрытой смены формата |
| S16 | Сообщение исчезло из отложки | Проверка | Публикация требует независимого подтверждения |

Локальные тесты проверяют время, версии утверждения, повторные запуски, частичную отправку, лимиты и проверки каналов с имитацией API. Внешняя приёмка отдельно: согласованный тестовый выпуск на трёх площадках, сначала проверка отложки, затем фактического выхода. Критерий — не раньше срока, задержка до пяти минут; это не SLA внешних сервисов.

Источники: [Telegram scheduled messages](https://core.telegram.org/api/scheduled-messages), [Telegram application](https://core.telegram.org/api/obtaining_api_id), [YouTube insert](https://developers.google.com/youtube/v3/docs/videos/insert), [YouTube publishAt](https://developers.google.com/youtube/v3/docs/videos#status.publishAt), [OAuth desktop](https://developers.google.com/youtube/v3/guides/auth/installed-apps).
