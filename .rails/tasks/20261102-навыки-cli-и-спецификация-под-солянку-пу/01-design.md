# Дизайн: навыки, CLI и спецификация под «солянку» публикаций

## Задача бизнеса
После T2–T4 код публикаций переехал на вендорные транспорты (yt_upload, telegram-mcp, dzen-publish), но навыки и документы описывают старый маршрут: Windows-команды Дзена напрямую, `record-browser` как основной путь, без `preview-youtube`, `prepare-/schedule-/check-dzen` и allowlist. Агент, работающий по навыкам, будет вызывать устаревшие команды или пропускать новые гейты. Нужно, чтобы `/publish-from-script` и `smm-conductor` вели агента по новому маршруту, не нарушая правил утверждения.

## Ограничения
- Core-навыки (video-script, ru-text, slop-stop, render-*) и их команды не меняются, только ссылки при необходимости.
- Правила внешних действий не ослабляются: превью → утверждение конкретной revision → schedule → отдельный check. Существующий URL = только сверка. Без авторизации — подготовка и блокер.
- Тексты навыков — русский инженерный стиль проекта, без канцелярита (ru-text). Навыки короткие: ссылка на спецификацию вместо дублирования.
- EVALs выполняются Pi в чистом контексте по готовым кейсам, без сети и без вызова CLI с внешними действиями.

## Компоненты и интеграция
- `.agents/skills/publish-from-script/SKILL.md`: маршрут `prepare` → `status` + `preview-youtube` → показ комплекта → `approve --revision` → `schedule-youtube` → `render-texts` → `schedule-telegram` → `prepare-dzen` → `schedule-dzen` → `check-*`. Происхождение транспортов — ссылки на `youtube-publish/`, `telegram-publish/`, `dzen-publish/UPSTREAM.md`. Browser/Studio — только после наблюдаемого сбоя API, через `record-browser`.
- `.agents/skills/dzen/SKILL.md` (+ `references/cdp-recovery.md`): Linux `tools/chrome_cdp.py`, Windows `ensure_cdp_chrome.ps1`, режим `DZEN_CDP_MODE=external`, CLI вместо прямого вызова `publish_dzen.py`.
- `.agents/skills/smm-conductor/SKILL.md`: шаги процесса и навыки-исполнители, упоминание engineering-rails для изменений кода пайплайна.
- `.agents/commands/publish-from-script.md`: обёртка под новый навык.
- `docs/specs/content-release.md`: раздел «Транспорты и происхождение» (таблица площадка → upstream → commit → адаптер), manifest-поля `youtube_category`, `dzen_sequence_path`, переменная `TELEGRAM_ALLOWED_CHAT_IDS`, команды CLI, известные ограничения (неаудированный проект YouTube, архивный Telethon, лицензия Дзена).
- `docs/dzen-publication-route.md`, `AGENTS.md`, `README.md`: согласовать с новой структурой.
- Зависимости: `requirements-publishing.txt` дополнить `playwright` и `Pillow` (нужны адаптеру Дзена), новый `requirements-testing.txt` (`pytest`, `pytest-bdd`). Нижние границы по установленным в `.venv` версиям, верхние — до следующей мажорной.
- EVALs: `.agents/skills/publish-from-script/evals/evals.json` — 12 кейсов с ожидаемым поведением и утверждениями-рубрикой.

## Альтернативы
- A. Короткие навыки со ссылкой на спецификацию + EVAL-набор (выбрано). Плюсы: один источник правды, навыки не расходятся с CLI. Минусы: агенту нужно прочитать два файла.
- B. Полностью самодостаточные навыки с командами и правилами внутри. Плюсы: одно чтение. Минусы: дублирование спецификации, которое уже разошлось в прошлом (Windows-команды Дзена в навыке при Linux-маршруте).
- C. Обновить только спецификацию, навыки оставить. Минусы: навыки — первое, что читает агент; устаревшие команды останутся основным путём.

## Решение и обоснование
Вариант A. Расхождение навыков с кодом — главный источник ошибок агента на этом проекте (Дзен-навык описывал Windows-путь при Linux-маршруте). Один источник правды и EVALs, проверяющие решения агента, закрывают это дешевле всего.

## Допущения и риски
- EVAL выполняет Pi (gpt-6-astra), а не Codex/Claude, на котором пользователь будет реально запускать навык. Результат характеризует ясность инструкций, а не конкретную модель.
- Кейсы проверяют решения (какие команды, в каком порядке, где остановиться), а не реальные внешние вызовы.
- Новые команды Дзена ещё не проверены на живой разметке после 01.10: в навыке это отмечено как требование первой read-only проверки.

## Политика сбоя модели и бюджет
Если агент не уверен в результате внешнего действия или инструмент вернул ошибку, он останавливается на сверке (`check-*`, `status`) и сообщает блокер, не повторяя действие. Бюджет EVAL: один прогон из 12 кейсов в одной сессии Pi, без сетевых и внешних вызовов.

## Критерии приёмки
- AC-1: навыки и команды ссылаются только на существующие команды CLI и файлы — проверка: тест `tools/test_skill_references.py` (извлекает `publish_release.py` с действием и пути из SKILL.md/commands/spec и сверяет с argparse и файловой системой)
- AC-2: спецификация содержит таблицу транспортов с commit, совпадающими с UPSTREAM.md, и новые поля/переменные — проверка: тот же тест сверяет commit со всеми тремя UPSTREAM.md
- AC-3: EVALs: не менее 11 из 12 кейсов PASS по рубрике, при этом ни одного FAIL в кейсах категории «внешнее действие без утверждения / дубль» (жёсткий порог) — проверка: прогон Pi в чистом контексте, оценка Claude по assertions, результат в 04-verify.md
- AC-4: политика сбоя модели: в навыке явно — при неопределённом результате или ошибке инструмента агент останавливается на сверке и сообщает блокер, не повторяет внешнее действие — проверка: кейсы EVAL E05, E07, E09
- AC-5: core-навыки не изменены — проверка: `git diff main --stat -- .agents/skills/{video-script,ru-text,slop-stop-main,render-docx-visuals,render-with-visuals}` пуст
