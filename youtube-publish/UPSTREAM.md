## Как используется

Адаптер `tools/publishing_youtube.py` загружает и кэширует модуль через `importlib`. Используемые символы upstream: `validate`, `build_body`, `preview`. Валидация вызывается на prepare для новых загрузок и перед insert; `preview-youtube --release DIR` показывает план под блокировкой выпуска, без `.env`, OAuth и сети. Для существующего `youtube_id` загрузочное превью отклоняется: такой выпуск допускает только сверку существующего ролика.

Тело insert строится через `build_body`: `private`, marker в тегах, без `publishAt`. Если `youtube_category` не задана, адаптер удаляет upstream-категорию 28, сохраняя прежнее поведение канала. Для `preview` вместо отсутствующей категории показывается `(channel default)`; эта подпись не отправляется в API.

Цикл resumable-загрузки адаптирован из `do_upload`: HTTP 500/502/503/504 допускают до пяти повторов после исходной попытки с задержками 2, 4, 8, 16, 32 секунды, всегда на том же запросе и без повторного insert. `do_upload`, `get_creds`, `service` и `whoami` напрямую не вызываются. OAuth остаётся проектным, токен — `.local/auth/youtube-token.json`, а не `.youtube/`.

Сохраняются проверка `YOUTUBE_CHANNEL_ID`, утверждённой ревизии, marker и `upload_attempted` до insert, защита от дублей и режим только чтения для `youtube_id`. После private insert адаптер устанавливает обложку, затем назначает `publishAt` по `Europe/Moscow` отдельным update и сверяет результат. Запас минимум одна минута проверяется перед insert и update. Реальный выход после срока подтверждает отдельный `check-youtube`; наличие расписания не доказывает публичную публикацию неаудированного проекта.

Вендорный файл остаётся неизменным. Самостоятельный запуск его загрузки не заменяет утверждение выпуска и не использует защитные проверки адаптера.

## Известные особенности upstream

- Рабочий сценарий upstream — черновик-only: по умолчанию `private`, затем публикация или отложка через Studio. Это не жёсткий запрет в коде: `build_body` уже передаёт заданные `privacy` и `publishAt`.
- Неаудированный Google Cloud проект принудительно ограничивается `private` на стороне YouTube; наличие `publishAt` само по себе не снимает ограничение.
- `REPO` — родитель каталога скрипта (здесь корень репозитория), `ROOT = REPO.parent` — родитель репозитория. Относительные пути плана, видео и описания отсчитываются от `ROOT`; адаптеру следует передавать абсолютные пути.
- OAuth-данные и токен сохраняются в `REPO/.youtube/`; каталог исключён из Git. Ссылки `tools/yt_upload.py` и `tools/yt_upload_SETUP.md` внутри исходников оставлены дословно; локально это `youtube-publish/yt_upload.py` и `youtube-publish/SETUP.md`.
- `whoami` печатает название канала, но не проверяет ожидаемый ID. Успешный `thumbnails.set` не гарантирует отображение обложки Shorts.
