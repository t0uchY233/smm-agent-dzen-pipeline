# Подключение и восстановление CDP

Пути указаны от корня репозитория. Это путь вне Codex: `tools/publish_release.py` через `tools/publishing_dzen.py` и `dzen-publish/`. В Codex Дзен публикуется во встроенном браузере (правило «Публикация в браузере Codex» в `docs/specs/content-release.md`).

## Предварительная проверка

На Linux используй `.venv/bin/python`, на Windows — `.venv/Scripts/python.exe`. Обе read-only диагностики должны получать один `DZEN_CDP_URL`. Общий helper читает `.env`, самостоятельный healthcheck — только окружение процесса. Из корня репозитория выполни:

```text
python tools/chrome_cdp.py --check
python -c "from dotenv import load_dotenv; import subprocess, sys; load_dotenv('.env', override=False); sys.exit(subprocess.call([sys.executable, 'dzen-publish/publish_dzen.py', '--healthcheck']))"
```

Обёртка загружает настройки локально и передаёт их healthcheck через унаследованное окружение, не печатая `.env` или его значения. Уже заданные переменные окружения имеют приоритет в обоих вызовах; между проверками не меняй окружение и `.env`. Не используй `cat .env`, вывод окружения или shell-tracing для диагностики. Команды выше только проверяют подключение, не запускают Chrome.

Эти проверки не создают черновик и не доказывают авторизацию. Перед изменением статьи адаптер отдельно проверяет целевой канал и права редактора. При первой работе после изменений разметки сначала проверь существующий утверждённый выпуск через `tools/publish_release.py check-dzen --release <dir>`; если выпуска ещё нет, доступность канала проверяется preflight до создания черновика.

## Linux, локальный режим

Если endpoint недоступен, запусти безопасный helper и повтори read-only проверку:

```text
python tools/chrome_cdp.py
```

Нужен desktop-сеанс либо постоянный Xvfb DISPLAY. Helper использует отдельный профиль `.local/auth/chrome-dzen`; обычные окна не закрывает. Путь браузера задаёт `CHROME_BINARY`, профиль — `DZEN_CHROME_PROFILE`. Локальный запуск от root запрещён: не обходи запрет через `--no-sandbox`; используй авторизованный внешний браузер или сообщи блокер. Не создавай временный DISPLAY, который исчезнет во время входа.

## Windows

Используй общий helper, особенно при нестандартном порте или профиле:

```powershell
.\.venv\Scripts\python.exe tools/chrome_cdp.py
```

Он читает `.env`, учитывает `DZEN_CDP_URL`, `DZEN_CHROME_PROFILE` и `DZEN_CDP_MODE`, а в локальном режиме вызывает `dzen-publish/ensure_cdp_chrome.ps1` с нужными портом и профилем. Профиль по умолчанию — `C:/temp/chrome-cdp-profile`. Прямой PowerShell-вызов без параметров не переносит эти настройки из `.env`; не используй его вместо общего helper при нестандартной конфигурации. Не запускай оба helper подряд без причины. Если нужен вход, пользователь выполняет его локально в этом профиле; не запрашивай cookies.

## Внешний CDP

`DZEN_CDP_MODE=external` означает: использовать уже доступный браузер, не запускать локальный Chrome даже при отказе endpoint. `DZEN_CDP_URL` допускает только HTTP loopback (`127.0.0.1` или `localhost`), без credentials, query, fragment и постороннего пути. Удалённый браузер подключается через заранее настроенный SSH-туннель. Не открывай CDP наружу и не меняй туннель или учётные данные без разрешения.

При недоступности внешнего CDP восстанови разрешённое существующее подключение либо сообщи блокер. Переключение на новый локальный профиль не восстанавливает прежнюю авторизацию.

## Бюджет восстановления и остановка

Подключение адаптера ограничено двумя попытками до редактора. При отдельной диагностике допускается один повтор helper и healthcheck; не оборачивай CLI в бесконечный цикл. Первый таймаут не доказывает `failed` и не разрешает повтор отправки. После изменения черновика или попытки назначения — только сверка существующего объекта, сохранение неопределённости и точный блокер.

После успешного preflight основной маршрут утверждённой версии: `tools/publish_release.py prepare-dzen --release <dir>` → `tools/publish_release.py schedule-dzen --release <dir>` → отдельный `tools/publish_release.py check-dzen --release <dir>`.

Если helper не восстановил соединение, передай пользователю ошибку CLI и действие из неё; не называй это политикой Дзена. `tools/publish_release.py record-browser` лишь сохраняет доказательство; он не управляет браузером.
